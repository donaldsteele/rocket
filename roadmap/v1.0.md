# Plan: rocket v1.0 — full build and release

## 1. Context & Scope

rocket is a single-binary LAN file transfer tool (`github.com/donaldsteele/rocket`), sibling of
netdiag (`c:\code\netDiscovery`) and bubbles (`c:\code\bubbles`). The scaffold (commit `497c45a`)
has: UDP beacon discovery, ed25519 node identity, TOFU trust store, two-phase push transfer
(offer -> accept -> stream), one HTTP port (UI, API, SSE, `/drop`, `/api/relay`), MCP server
(`list_peers`, `send_file`, `get_status`), Alpine web UI.

v1.0 delivers, on top of the scaffold:

- **Security hardening** of the scaffold (signed offers, loopback-only control API, CSRF/Host
  checks, server-side drop tokens, limits). The scaffold is not safe on a shared LAN today.
- **Multi-file and folder sends** in one offer, one accept prompt, per-file progress.
- **Transfer history and cancel** (both ends).
- **mDNS** (`_rocket._tcp.local`) alongside the UDP beacon.
- **UI to netdiag parity**: sidebar app shell, Settings (name, download folder, trusted senders),
  LAN drop page, accessibility.
- **Desktop tray app** (`tray/`, separate module).
- **Packaging and docs**: zips for windows/darwin/linux x amd64/arm64, SHA256SUMS, licenses,
  exe icon/version info, CHANGELOG, docs, CI.
- **Release**: tag `v1.0.0`, local dist built and smoke-tested; then published to a new public
  GitHub repo `donaldsteele/rocket` with a GitHub release (publish step run by the main session
  after verifying the dist, not by a workflow agent).

**Out of scope for v1.0:** HTTPS/local CA (TOFU over plain HTTP was chosen; documented),
resume of interrupted transfers, code signing/notarization, macOS tray binaries (build from
source; needs cgo), app stores, internet/relay transfer.

## 2. Locked Decisions (Non-Negotiable)

1. **Stack and shape.** Go 1.26 single binary, stdlib-first, `CGO_ENABLED=0` for the main
   binary on all six targets. Layout `cmd/rocket`, `internal/*`, `web/` (vanilla JS + vendored
   Alpine, embedded with `embed`), warm netdiag theme tokens, Inter + JetBrains Mono embedded,
   no outside requests from the page. New third-party deps allowed only: `brutella/dnssd`
   (mDNS, same as bubbles), `fyne.io/systray` (tray module only), `go-winres` (build tool),
   plus what the MCP SDK already pulls in.
2. **Trust model.** Trust-on-first-use with **proof of key possession**: every peer offer is
   ed25519-signed by the sender; the receiver verifies the signature, that the fingerprint
   derives from the presented public key, that the offer names the receiver's fingerprint, and
   freshness/nonce. The trust store pins the full public key. Browser drops use server-issued
   tokens. Traffic is plain HTTP (documented). Agents (MCP) can never accept a transfer, trust
   or revoke a sender, change settings or quit.
3. **Two network surfaces on one port (29005).** LAN surface (any host): `GET /api/hello`,
   `POST /api/offer`, `POST /api/recv`, the drop page and `/drop/*`. Everything else (full UI,
   control and read APIs, SSE) is **loopback-only** with a Host-header allowlist, and every
   non-GET control call requires the header `X-Rocket-CSRF: 1`. Discovery: UDP beacon on 29006
   plus mDNS; both feed one registry keyed by fingerprint.

## 3. System Architecture & Module Layout

- **Target Modules/Packages**
  - `cmd/rocket/` — commands `ui` (default), `send`, `recv`, `mcp`, `version`; shared flags
    `--port`, `--beacon-port`, `--data-dir`, `--download-dir`, `--name`, `--no-mdns`.
  - `internal/config/` — paths, ports, flag/env overrides, `settings.json` load/save.
  - `internal/node/` — identity; add `PublicKeyB64()`, `Verify(pub, msg, sig)`.
  - `internal/peers/` — trust store pinning `{fingerprint, name, pub, approved_at}`.
  - `internal/protocol/` (new) — wire types, canonical signing bytes, signature/freshness
    checks, nonce cache, manifest types and validation. Single source of truth for the wire.
  - `internal/transfer/` — sender (`Send`, `SendReader`, multi-file tar streaming), receiver
    helpers (safe extraction, `.rocket-part` temp files), transfer manager (IDs, cancel).
  - `internal/history/` (new) — JSONL history store.
  - `internal/discovery/` — `registry.go`, `beacon.go`, `mdns.go`.
  - `internal/httpapi/` — `server.go` (routing), `middleware.go` (loopback/Host/CSRF), handlers
    split by area (`peer.go`, `control.go`, `drop.go`, `events.go`).
  - `internal/mcpserver/` — tools + authority test.
  - `web/` — `index.html` (full UI), `drop.html` + `drop.js` (LAN drop page), `app.js`,
    `styles.css`, `theme.js`, `icons.svg`, `favicon.png`, vendor.
  - `tray/` — separate module `github.com/donaldsteele/rocket/tray`, talks to the local API only.
  - `tools/mkzip`, `tools/licenses`, `tools/icongen`; `scripts/build.sh`, `scripts/build.ps1`;
    `cmd/rocket/winres/`; `.github/workflows/ci.yml`; `docs/`.
- **Data Models** (all in the data dir, `os.UserConfigDir()/rocket` unless `--data-dir`)
  - `node.key` — ed25519 private key (0600).
  - `trusted.json` — `[{fingerprint, name, pub (base64), approved_at}]`.
  - `drop_tokens.json` — `[{token_hash, created_at, expires_at}]` (30-day expiry; store SHA-256
    of the token, never the token).
  - `settings.json` — `{device_name, download_dir, auto_accept_trusted (default true)}`.
  - `history.jsonl` — one entry per transfer: `{id, dir:"in"|"out", peer_name, peer_fp, files,
    bytes, started, ended, result:"ok"|"declined"|"cancelled"|"error"|"timeout", error}`;
    capped at 1000 entries (compacted at start).
- **Core Pipeline**
  - Discovery: beacon + mDNS -> `Registry` (merge by fp, `via: ["beacon","mdns"]`, TTL expiry).
  - Send: resolve peer (name, fp prefix, or `host:port`) -> `GET /api/hello` (receiver fp, pub)
    -> signed `POST /api/offer` with manifest -> wait (receiver prompts unless trusted and
    auto-accept) -> `POST /api/recv?token=` streaming body: raw bytes for a single file, tar for
    multi-file/folder -> receiver writes `*.rocket-part`, verifies byte counts, renames.
  - Every transfer has an ID; events carry it; transfer manager holds cancel funcs; history entry
    written on finish.

## 4. Interfaces & Contracts

- **Protocol v1** (`internal/protocol`, documented in `docs/protocol.md`)
  - `GET /api/hello` -> `{proto:1, name, fp, pub, version, os}`.
  - `POST /api/offer` body: `{proto:1, sender_name, sender_fp, sender_pub, receiver_fp, ts,
    nonce, manifest:{kind:"file"|"multi", entries:[{path, size, mode}], total}, sig}`.
    `sig` = ed25519 over `"rocket-offer-v1\n" + receiver_fp + "\n" + sender_fp + "\n" + ts +
    "\n" + nonce + "\n" + hex(sha256(canonical manifest JSON))`.
    Receiver rejects (400) if: proto != 1, `fp != hex(sha256(pub))[:16]`, receiver_fp != own fp,
    `|now-ts| > 5m`, nonce reused (LRU 4096), bad sig, manifest invalid (entry paths must be
    relative, clean, no `..`, no absolute/volume/UNC, no NUL, <= 10,000 entries, total <= 1 TiB).
    Trusted = fp in store AND pub matches pinned pub. Reply `{accepted, token, transfer_id,
    reason}`; long-poll up to 2 min.
  - `POST /api/recv?token=` — one-shot token (10-min TTL); `Content-Length` must equal manifest
    total for `kind:file`; for `multi` the body is a tar whose entries must match the manifest
    exactly (names, sizes, count). Any mismatch aborts and deletes partials.
  - Limits: offers body <= 1 MiB, pending offers <= 16 total and <= 4 per remote IP.
- **Drop (LAN, browser guests)**: `GET /` on a non-loopback request serves `drop.html`;
  `POST /drop/offer` `{files:[{name,size}]}` -> long-poll accept (skipped if a valid
  `rocket_drop` cookie token) -> `{token}` and sets `rocket_drop` (HttpOnly, SameSite=Strict,
  30 days) on first accept; `POST /drop/upload?token=` streams multipart, one file per part,
  names/sizes must match the offer. No `ParseMultipartForm` buffering.
- **Control API (loopback + Host allowlist + `X-Rocket-CSRF: 1` on non-GET)**:
  `GET /api/self`, `GET /api/peers`, `GET /api/incoming`, `GET /api/transfers`,
  `GET /api/events` (SSE; events: `offer`, `offer_gone`, `progress`, `done`, `sent`, `error`,
  `cancelled`, all with `transfer_id`), `POST /api/accept {id, accept, trust}`,
  `POST /api/send {peer, paths[]}`, `POST /api/relay?peer=` (multipart, multiple parts ->
  multi), `POST /api/cancel {transfer_id}`, `GET /api/history?limit=`, `POST /api/history/clear`,
  `GET/PUT /api/settings`, `GET /api/trusted`, `POST /api/trusted/revoke {fingerprint}`,
  `POST /api/quit`.
- **MCP** tools exactly: `list_peers`, `send_file {peer, paths[]}`, `get_status`,
  `list_history {limit}`. Authority test pins this set and asserts no accept/trust/settings/quit
  tool exists.
- **CLI**: `rocket send <peer|host:port> <path>...`, flags as in §3; `rocket version` prints
  `rocket 1.0.0`. Version injected with
  `-ldflags "-X github.com/donaldsteele/rocket/internal/buildinfo.Version=$VERSION"`.
- **Web layout & accessibility**: netdiag app shell — sidebar (Send, Transfers, History,
  Settings) collapsing to icon rail then a Menu button on narrow widths; top bar with this host,
  theme toggle, Quit. Incoming offers as a sticky prompt with Accept / Decline / "Always accept
  from this host". WCAG 2.x AA contrast (existing tokens), visible focus rings, full keyboard
  use, `aria-live` for offers and completions, status as shape + word (never colour alone),
  `prefers-reduced-motion` honoured, works at 360px width. Drop page: same tokens, one big
  "Choose files" button plus drag-and-drop, per-file progress, plain-words status.

## 5. Risk Mitigation Matrix

1. **Remote control/exfiltration via LAN-exposed API** (scaffold bug). Mitigation: middleware
   classifies every route as LAN or loopback in one table; loopback routes check
   `RemoteAddr` is loopback AND Host is `127.0.0.1:<port>`, `localhost:<port>` or
   `[::1]:<port>` (DNS-rebinding defence) AND CSRF header on non-GET. Table-driven test calls
   every route from a non-loopback address and asserts 403.
2. **TOFU spoofing / replay.** Mitigation: signed offers bound to receiver fp, timestamp window,
   nonce LRU, pinned full public key; tests for forged fp, wrong receiver, stale ts, replay,
   pub mismatch with trusted fp.
3. **Path traversal / zip-slip / disk abuse on receive.** Mitigation: manifest validation in
   `internal/protocol`; extraction joins under a per-transfer root and re-checks with
   `filepath.Rel`; rejects symlinks/devices; exact size accounting; `.rocket-part` + rename;
   Windows reserved names and trailing dots/spaces sanitized; fuzz/table tests.
4. **Concurrency bugs (cancel, SSE, pending maps).** Mitigation: one transfer manager owns state
   behind a mutex; contexts everywhere; tests cancel mid-stream on both ends and assert partials
   are removed and history says `cancelled`; `go test -race` in CI (linux).
5. **Release breakage across 6 targets + tray.** Mitigation: CI matrix (ubuntu/windows/macos)
   builds and tests; build script fails on missing docs/licenses; release milestone smoke-tests
   the built windows/amd64 binary with two local instances doing a real folder transfer and
   compares SHA-256 of every file.
