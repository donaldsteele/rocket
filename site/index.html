Send files to the computer across the room.

Files and whole folders, straight from one computer to another on your local network. No cloud, no account, no internet.

Run rocket on each computer. It finds the others by itself, and the person receiving says yes before anything is saved. Files between rocket apps are encrypted on the way, and a transfer cut off by a dropped connection carries on where it stopped. The Android app sends and receives too, other phones and guests send from a page in their browser, and Claude can send files for you over MCP.

How it works

Send in three steps.

Every computer runs rocket. There is no server to set up and nothing to pair: the computers on your network show up by themselves within a few seconds.

  1. Run rocket on each computer. It prints its addresses and opens its page in your browser.
  2. Pick a computer under Computers on your network, then Send files or Send folder.
  3. Accept on the other end. Tick Always accept from this host to skip the prompt next time.
rocket
rocket 1.1.0 name: Studio-PC fingerprint: cfe4dd4a4437c183 received to: C:\Users\you\Downloads\rocket open: http://127.0.0.1:29005/ drop page: http://192.168.1.20:29005/

Trust on first use

Nothing is saved until you say yes.

The first offer from a new sender asks you, with the sender's name, its fingerprint, the number of files, the total size and the first few names. Always accept from this host remembers that sender's key, so the next transfer just arrives.

When the connection drops

It carries on where it stopped.

Wi-Fi drops out, a laptop goes to sleep, someone walks out of range. Once a transfer has been accepted, rocket keeps what already arrived and sends only the rest.

  1. sendingAcceptedThe receiver said yes and the files are on their way, encrypted.
  2. cutConnection lostThe receiver keeps what arrived as .rocket-part files, for up to 24 hours.
  3. retryReconnecting 1/5The sender tries again after 2, 5, 10, 20 and 30 seconds, with a new signed offer.
  4. doneCarries onNo second prompt. Only the missing bytes are sent, once the sender has checked that what already arrived still matches its file.

After the fifth try the send shows Interrupted, with Resume and Discard, for 24 hours; with rocket send, run the same command again. Every send between rocket apps carries on like this: from the desktop page, the Android app, rocket send and Claude. Files you pick in the desktop page stay in your browser, so keep the page open while it reconnects; after a reload, Resume asks you to pick the same files or folder again and checks that they match. Only drops from the browser drop page start over. Cancel or Decline on either side never keeps anything.

What it does

Everything you need to move files across the room.

And nothing in between: the bytes go from one computer straight to the other, written to disk as they arrive.

Finds the others

A UDP beacon and mDNS (_rocket._tcp.local) announce each computer. Both feed one list keyed by fingerprint, and computers that go quiet drop off.

Files and whole folders

Many files or a whole folder go as one transfer with one approval and per-file progress. Empty folders, unicode names and 0-byte files arrive intact.

You say yes first

The first transfer from a new sender asks you. Received files land in Downloads/rocket, or any folder you choose in Settings.

Encrypted on the way

File contents between rocket apps are encrypted with keys made fresh for every transfer, and a change in transit is caught. Offers and replies are signed, so nobody can pose as a sender you trust. Names and sizes are not encrypted.

Phones too

The Android app sends and receives like a computer. Any other phone, or a guest without rocket, opens the computer's drop page in a browser and uploads straight to it.

Picks up where it stopped

When the connection drops, the sender reconnects by itself and sends only what is missing, without a second prompt, whether you sent from the desktop page, the phone, the command line or Claude. Either side can still cancel, and History keeps the last 1000 transfers.

Tray icon

On Windows and Linux, rocket-tray shows whether rocket runs and how many peers it sees, and gets a red badge when someone is waiting for your answer.

Claude can help

Over MCP, Claude can list the computers on your network and send files. It can never accept a transfer: that stays with you.

Android

rocket in your pocket.

The Android app sends to and receives from every rocket computer and phone on the Wi-Fi, with the same signed offers, the same encryption and the same yes-first prompt. It runs the desktop's own protocol code, so a phone is just another peer. Android 8.0 or later.

Receive

On when you want it, off when you don't.

Turn on Receive files and the phone shows up on every computer under its own name. A notification says it is listening, offers pop up with Accept and Decline, and files land in Download/rocket. Turn it off and the phone stops listening.

History, the device name and your trusted senders with Revoke work just as on the desktop. Light and dark themes, TalkBack labels and text up to 200%.

Other phones and guests

No app? Just a page.

An iPhone, a guest's phone or a laptop without rocket opens the drop page address rocket prints, such as http://192.168.1.20:29005/, on the same Wi-Fi. They choose files, you accept on the computer, and the files land in your download folder.

  1. openThe addressThe drop page says which computer it sends to.
  2. chooseChoose filesOr drag them onto the page. Any number at once.
  3. acceptYou say yesThe offer appears on the computer, marked from a web browser.
  4. doneSentEach file shows its own progress, then Sent.

The drop page is not encrypted. Browsers only allow web encryption on HTTPS pages, and rocket serves plain HTTP, so files dropped from a browser cross the Wi-Fi in clear: someone on the network could read or change them. The computer marks these offers and transfers Not encrypted, and a drop cut off by the network starts over. For private files, use the app on both ends.

After your first accept, that browser can drop again for 30 days without asking while Accept files from trusted senders without asking is on. Turn it off in Settings to be asked every time.

Connect Claude

Ask Claude to send it over.

rocket mcp is a Model Context Protocol server over stdio. Claude can see the rocket computers on your network, send files and folders to one of them (encrypted, and resumed if the connection drops), and read this computer's status and history. Accepting stays with you.

Terminal · connect Claude Code
$claude mcp add rocket -- "C:\path\to\rocket.exe" mcp # Windows
$claude mcp add rocket -- /path/to/rocket mcp # macOS / Linux
# example request
>Send the photos folder on my desktop to Laptop.
list_peers → send_file {peer: "Laptop", paths: [...]} → waits for Laptop to accept

Claude Desktop and other clients: add a stdio server with the command rocket and the argument mcp. It runs its own discovery, so the rocket window does not need to be open. Full reference: docs/mcp.md.

MCP tools, exactly four

  • list_peers rocket computers on the network
  • send_file Files and folders to a peer, one approval
  • get_status This computer, transfers in progress and interrupted sends
  • list_history Recent transfers, newest first
  • Never: accept a transfer, trust or revoke a sender, change settings or quit rocket. A test pins the set.

Security

Made for networks you trust.

Anyone on your network can offer you files; nothing is saved until you accept, and the files themselves travel encrypted between rocket apps. Here is exactly what rocket protects, and what it does not.

  • Encrypted file contents. Between rocket apps (desktop and Android, 1.1 and later) every file is encrypted with ChaCha20-Poly1305 under a key made for that one transfer from fresh X25519 keys. A changed, missing or reordered byte fails the check and the receiver throws the transfer away. A recorded transfer stays unreadable even if a device key is stolen later.
  • Trust on first use, pinned by key. Each device has an ed25519 key made on first run. Always accept from this host pins that sender's full public key, not its name or IP address. The first offer from a new device is only a claim: compare the fingerprint before you trust it.
  • Signed offers and replies. The offer signature covers the receiver, the sender, a timestamp, a one-time nonce, the sender's encryption key and a hash of the file list; the receiver signs its answer and its own encryption key. Redirected, replayed and stale offers are refused, and nobody in between can swap in their own key.
  • Controls stay on this computer. The full page and every control API answer only on loopback, with a Host header allowlist and an X-Rocket-CSRF header on every change. Other computers reach only the peer protocol and the drop page.
  • Safe on disk. Paths that climb out of the download folder, symlinks, devices and Windows reserved names are refused or made safe. Files are written as .rocket-part and renamed when complete. A transfer resumes only for the same sender key and the same files, and only at the point the receiver offered.
  • Limits. An offer waits at most 2 minutes, at most 16 wait at once (4 per address), and a transfer is capped at 10,000 entries and 1 TiB. Kept partial transfers are removed after 24 hours.
  • Phones listen only when asked. The Android app runs its receiver only while Receive files is on, with a notification that says so, and serves only the peer protocol: no drop page, no control API. Its key stays out of backups.

What is not encrypted: rocket runs over plain HTTP and encrypts the file contents only. Anyone who can watch your network can still see file and folder names, sizes and the folder layout (offers are signed, not encrypted), device names, fingerprints and versions, and who sends to whom, when and how much. Files from the browser drop page are not encrypted at all. Someone on the network can also cut a transfer off. Use rocket on networks you trust, such as home or the office, and put files in an encrypted archive first if their names must stay private.

Encrypted to the device you picked: there are no certificates, so rocket trusts a device's key the first time it sees it. Picking a computer or phone from the list encrypts to that device's fingerprint; sending to a typed address encrypts to whoever answers there. Compare fingerprints when it matters.

Also worth knowing: rocket 1.1 does not talk to rocket 1.0 in either direction, and says which side needs updating. The desktop binaries are not code-signed, so check them against SHA256SUMS. The Android APK is signed with the project's release key, which never leaves the maintainer's machine. The full threat model is in docs/security.md.

  • TCP 29005Transfers and the drop page (the page itself answers only on this computer)
  • UDP 29006The discovery beacon
  • UDP 5353mDNS, optional (--no-mdns turns it off)

Download

Unzip it, run it, send.

One file per platform, no installer and no runtime to add. Put rocket on every computer and Android phone you want to send between. The Windows and Linux zips include the tray app.

Update every device to 1.1. rocket 1.1 encrypts transfers with a new protocol and cannot send to or receive from rocket 1.0, in either direction. Older devices show as Needs update, and an old sender is told to update. Install 1.1 over 1.0: settings, trusted senders, history and the phone's fingerprint stay.

Run ./rocket (chmod +x rocket rocket-tray if needed). ./rocket recv runs without a browser, for example on a Pi. With a firewall on, open TCP 29005 and UDP 29006 (and UDP 5353 for mDNS).

Not in the Play Store. Open the download on the phone, tap Settings and turn on Allow from this source when Android asks, then Install. If Play Protect warns about an unknown app, choose More details, then Install anyway. Turn on Receive files in the app to get files on the phone.
